# 言霊バトル 仕様書（Ver.0.1）

最終更新：2026-09-28（改訂10：バランス調整・CPU・出題条件）

このファイルが仕様の正（Single Source of Truth）。仕様変更はまずここへ反映してから実装する。

## 0. 前提

- ブラウザゲーム。仲間内で遊ぶ試作版
- HTML / CSS / JavaScript（ES Modules、ビルドなし、外部ライブラリなし）
- ログインなし・広告なし・スタミナなし・オンライン対戦なし（Ver.0.1）
- データ保存は localStorage
- スマホのブラウザで問題なく遊べること（レスポンシブ対応）
- 公開は GitHub Pages 等の無料ホスティングを想定

## 1. コンセプト

**完全実力勝負。** 成長要素・自分辞書・ステータスは存在しない。
勝敗を決めるのは「どれだけ長い言葉を、どれだけ速く出せるか」だけ。

## 2. 画面遷移

```
タイトル ─┬─ バトル → CPU選択（難易度） → バトル → 結果 → タイトル
          └─ 戦績
```

| 画面 | 内容 |
|---|---|
| タイトル | 「バトル」「戦績」を表示 |
| CPU選択 | 難易度別にCPUを選ぶ（おすすめ表示なし） |
| バトル | お題・両者HP・残り時間・入力欄・相手の回答済み表示・判定タイムの結果 |
| 結果 | 勝敗表示。CPU戦はレート変動なし |
| 戦績 | CPU戦の勝ち・負け・引き分け・勝率・直近30試合（対人戦は Ver.0.1 では表示しない） |

## 3. バトル

### 3.1 流れ（1問ごと）

1. お題を出す（例：「あ」から始まり「で」で終わる言葉）
2. 出題と同時に、プレイヤーとCPUの回答時間を計測開始
3. **回答受付**：各プレイヤーは「回答する」を押して回答を確定するか、制限時間になるまで待つ。
   この間はまだ攻撃しない
   - 確定前は入力を自由に修正できる
   - **「回答する」を押したらその回答はロックされ、その問題では再入力できない**
   - 入力欄が空のときは「回答する」を押せない
   - IME変換中のEnter等による誤送信は防止する
   - 制限時間までに確定しなかった側は時間切れ（入力途中の文字は回答として扱わない）
4. 両者の回答状態が確定したら **判定タイム** に入る（§3.2）
5. **攻撃**：有効回答の側だけ、攻撃順（§3.2）に従って攻撃する
6. どちらかのHPが0になったら決着。そうでなければ次のお題へ

**判定タイムまで相手に見せない情報**：回答した言葉・文字数・回答時間。
見せてよいのは「相手が回答済みかどうか」だけ（例：`CPU 回答済み ✓`）。
判定タイムに入ったら、両者の回答・回答時間・文字数・正誤判定（無効ならその理由）を公開する。

### 3.2 判定タイムと攻撃順

判定タイムでは、両者それぞれについて次を判定する：

- 回答時間
- 最初の文字が一致しているか
- 最後の文字が一致しているか
- 最低文字数を満たしているか
- 公式辞書または追加辞書に存在するか
- 読みの文字数

**有効回答だけがダメージ計算の対象。** 時間切れ・無効回答は攻撃なし。
無効の理由：最初の文字が違う／最後の文字が違う／最低文字数未満／辞書にない／使えない文字（漢字・英数字・「〜」等）を含む、など。
無効と判定されても、その問題では再入力できない。

回答時間はミリ秒単位で比較する。

| 判定結果 | 攻撃 |
|---|---|
| 両者とも有効・回答時間が異なる | 回答時間が短い側が先攻。先攻の攻撃で相手HPが0なら決着（後攻の攻撃なし）。残っていれば後攻も攻撃 |
| 両者とも有効・回答時間が完全に同じ | **同時攻撃**。両者のダメージを同時に適用する（下表） |
| 片方だけ有効 | 有効な側だけ攻撃 |
| 両方無効／両方時間切れ／片方無効＋片方時間切れ | 誰も攻撃せず次のお題へ |

同時攻撃の結果：

| 適用後のHP | 結果 |
|---|---|
| 片方だけ0 | 生き残った側の勝利 |
| 両方0 | バトル引き分け |
| 両方残る | 次のお題 |

ランダムな先攻決定は行わない。

回答速度は **攻撃順の決定** と **ダメージ計算（時間補正 §3.4）** の両方に影響する。

### 3.3 ルール

- 制限時間：1問15秒（`config.js` で変更可）
- HP：両者同じ値（`config.js`、仮に100）
- 同じ言葉は何度使ってもよい（使用済みチェックなし）
- 引き分け（無攻撃）：**3問連続で、どちらからも有効な攻撃が発生しなかった** → 引き分け（CPU戦なら `record.cpu.draws` +1）。回数は `config.js` で管理
  - 対象：両方時間切れ／両方無効回答／片方時間切れ＋片方無効回答
  - 片方でも有効回答をして攻撃が発生したら、連続カウントは0に戻る
- 引き分け（相打ち）：同時攻撃で両者のHPが同時に0になった場合（§3.2）
- 中断：バトル開始後に「やめる」を選んだ場合は敗北扱い（→ §3.5）

### 3.4 ダメージ

係数はすべて `config.js` に置く。

```
ダメージ計算用文字数 = min(読みの文字数, MAX_DAMAGE_LENGTH)   // MAX_DAMAGE_LENGTH = 20
長さ補正 = 1 + (ダメージ計算用文字数 - 2) × 0.175
時間補正 = 1.5 - (回答秒数 / 制限時間)        // 0秒で1.5、制限時間ちょうどで0.5
ダメージ = max(1, round(11 × 長さ補正 × 時間補正))
```

目安（HP100）：1試合は平均 約6.5〜7.5問。
「短い言葉を即答」と「時間をかけて長い言葉」は拮抗するよう調整している（シミュレーションで約49%対51%）。
例：3文字を4.6秒 → 約15、10文字を11.4秒 → 約20。速い側は先攻でき、とどめを先に刺せる。

**実際の文字数とダメージ計算用文字数は分けて扱う。**
20文字を超える言葉も、正しい言葉なら回答として有効で、表示も実際の文字数で行う。ダメージ計算だけ20文字分として扱う。

| 実際の文字数 | ダメージ計算用文字数 |
|---|---|
| 8 | 8 |
| 15 | 15 |
| 20 | 20 |
| 25 | 20 |
| 50 | 20 |

判定タイムでは、上限を超えた場合に「25文字（ダメージ計算は20文字）」のように両方を表示する。
上限は `config.js` の `damage.maxDamageLength` で変更できる。

### 3.5 中断・離脱

将来の対人戦（ランダムマッチ）と同じ考え方に揃える：**「バトルを開始したら、決着するまで抜けると負け」**。

「バトル開始」＝ バトル前の説明画面で「スタート」を押した時点。

| ケース | 扱い |
|---|---|
| 「やめる」ボタン（バトル開始後） | 即座に敗北として記録（理由：途中でやめた） |
| リロード・タブやブラウザを閉じる・ブラウザの「戻る」でサイトを離れる（バトル開始後） | 次回起動時に敗北として1回だけ記録し、タイトル画面で通知する（理由：途中離脱） |
| タイトル・難易度選択・バトル前の説明画面での離脱／「やめる」 | 敗北にしない（何も記録しない） |
| 決着後（判定タイムの結果表示・結果画面）での離脱 | 決着時点で記録済みなので影響なし |

実装方針：

- バトル開始時に localStorage へ `activeMatch`（進行中フラグ）を書き込む。各問の開始時に現在の問題番号を更新する
- 決着した瞬間（判定タイムで決着が決まった時点）に、戦績の記録と `activeMatch` の解除を1回の保存で行う
- 起動時に `activeMatch` が残っていれば「途中離脱による敗北」として該当モードの戦績と履歴に1回だけ反映し、同じ保存で解除する
- 戦績の記録は `activeMatch` がある場合だけ行う（二重記録の防止）
- `activeMatch` は `mode`（`"cpu"` / 将来 `"ranked"`）を持ち、記録先の戦績をモードで振り分ける。対人戦ではサーバー側の判定が正となり、ローカルの目印は表示用の補助になる想定
- バトル途中の状態からの再開（レジューム）は行わない

### 3.6 文字の扱い

| 項目 | 扱い |
|---|---|
| カタカナ入力 | 判定用にひらがなへ正規化（ヴ→ゔ）。「ー」は正規化しない |
| 末尾の「ー」 | 「ー」のまま末尾判定（コーヒー → 末尾「ー」） |
| 長音の表記 | 有効なのは「ー」だけ（半角「ｰ」は「ー」に正規化）。「〜」「～」「－」「-」等は「ー」とみなさず、その回答は無効 |
| 最初の文字として出題しない | 「ー」「ん」「を」「ゔ」「ゐ」「ゑ」、小書き文字（ぁぃぅぇぉ・ゃゅょ・っ・ゎ・ゕゖ） |
| 最後の文字として出題しない | 「を」「ゔ」「ゐ」「ゑ」、小書き文字（ぁぃぅぇぉ・ゃゅょ・っ・ゎ・ゕゖ） |
| 「ん」「ー」 | 最後の文字として出題可 |
| 濁点・半濁点 | 区別する（て／で、は／ば／ぱ は別の文字） |
| 文字数 | 読みの文字数をそのまま数える（「きゃ」=2、「ー」=1） |
| 回答の入力 | Ver.0.1 はかな（ひらがな・カタカナ）のみ |

**出題可能文字と回答の有効性は別物。**
「出題しない」制限は、ランダム出題で極端に答えにくい・不自然なお題を作らないためのもの。
回答の側では、ひらがなと「ー」でできた読みであれば、どの文字で始まり・終わっても有効
（例：「っ」で終わる言葉でも、公式辞書にあり、お題に一致すれば有効）。
実装上も `isPromptFirstChar` / `isPromptLastChar`（出題用）と `isReading`（回答用）を分離する。

## 4. CPU

- 出題用の一般語プール（`data/prompt-pool.json`）から回答する
- CPUの回答もプレイヤーと同じ判定タイム・同じ判定処理を通す
- CPUにステータス・固定レートは持たせない
- 強さは「回答時間」「選ぶ単語の文字数」「時間切れ率」の3つだけで調整する
- 回答時間 ＝ 考える時間（正規分布でばらつく。下限あり）＋ 1文字あたりの入力時間 × 文字数。
  毎回違う秒数になり、長い言葉ほど時間がかかる。制限時間を過ぎたら時間切れ
- 文字数は、難易度ごとの分布（平均・ばらつき）から狙う文字数を引き、お題の候補の中で最も近い語を選ぶ（毎回最長語を選ぶわけではない）
- 同じバトルの中で使った語は、他に候補がある限り選ばない
- 時間切れ率：わざと答えない確率（考えすぎによる時間切れとは別）

| 難易度 | 考える時間（平均 / ばらつき / 下限） | 入力時間/文字 | 狙う文字数（平均 / ばらつき） | 時間切れ率 |
|---|---|---|---|---|
| かんたん | 6.0秒 / 2.0 / 2.5秒 | 0.50秒 | 3 / 0.8 | 12% |
| ふつう | 5.0秒 / 1.6 / 2.0秒 | 0.40秒 | 4.5 / 1.2 | 10% |
| むずかしい | 4.2秒 / 1.2 / 1.8秒 | 0.35秒 | 6 / 1.5 | 6% |

実際の平均（シミュレーション）：かんたん 7.6秒・3.1文字、ふつう 6.5秒・3.7文字、むずかしい 5.6秒・3.9文字。
選べる語は出題用プールの候補に限られるため、狙う文字数より短くなりやすい。

想定勝率（「ふつうの人」モデル相手のシミュレーション、各300試合）：かんたん 約85%、ふつう 約55%、むずかしい 約25%。
数値は `src/cpu/enemies.js`、シミュレーターは `tools/sim/`。

## 5. レーティング

- **CPU戦ではレーティングを一切変動させない。**
  CPU戦は「練習・操作確認・ゲームバランス確認」のためのモード
- 対人レーティングは将来実装の「ランダムマッチ」でのみ変動する
- Ver.0.1 では `rating.ranked` をデータ上に持つだけで未使用

## 6. 戦績

- CPU戦の勝敗・引き分けを保存する
- 直近30試合の履歴を保存する（件数は `config.js`）。新しい順
- 対人戦（ranked）の戦績・履歴とは分離する。Ver.0.1 では ranked は未使用で、画面にも出さない
- 戦績画面の表示：CPU戦の勝ち・負け・引き分け・勝率・直近30試合
- 勝率 ＝ 勝ち ÷ 試合数（引き分けを含む全試合）。0試合なら「—」

## 7. データ構造

### 7.1 単語

```js
{ surface: "東京都千代田区", reading: "とうきょうとちよだく" }
// reading：正規化済みひらがな（「ー」は保持）
// 判定・文字数には reading、表示には surface を使う
```

### 7.2 セーブデータ（localStorage key: `kotodama.save`）

```js
{
  version: 1,
  rating: {
    ranked: null          // 将来のランダムマッチ用。Ver.0.1 未使用
  },
  record: {
    cpu:    { wins: 0, losses: 0, draws: 0 },
    ranked: { wins: 0, losses: 0, draws: 0 }   // Ver.0.1 未使用
  },
  history: {            // 直近30試合。新しい順
    cpu: [
      {
        at: "2026-09-28T09:30:00.000Z",  // 決着日時（ISO 8601）
        mode: "cpu",
        cpuId: "hard",                    // CPU難易度
        outcome: "win",                   // win / lose / draw（自分から見た結果）
        reason: "ko",                     // ko / double-ko / no-attack / forfeit / abandon
        rounds: 8                         // 何問目で決着したか
      }
    ],
    ranked: []                            // Ver.0.1 未使用
  },
  activeMatch: null     // 進行中フラグ（§3.5）。例：{ mode: "cpu", cpuId: "normal", startedAt: "…", round: 3 }
}
```

- `rounds`：決着した問題の番号。「やめる」の場合は、出題中なら出題中の問題番号、判定結果の表示中ならその問題番号。途中離脱の場合は最後に始まった問題番号（1問目の出題前なら0）
- 読み込んだデータが壊れている・形式が違う場合は、読める項目だけ残して既定値で補う
- localStorage が使えない環境（プライベートモード等）でも遊べるよう、保存に失敗してもゲームは続行する（その場合、戦績はページを閉じるまでしか残らない）

## 8. 単語判定

```
入力
 ↓ ① 形式チェック（空でない・長音は「ー」のみ・かなのみ・2文字以上）
 ↓ ② 条件チェック（最初の文字・最後の文字）
 ↓ ③ 公式辞書（ライセンス上問題のない既存日本語辞書）
 ↓ ④ ゲーム独自の追加辞書（開発側が管理する JSON）
 → どこかで不合格なら無効（その問題では攻撃なし。再入力はできない）
```

- 判定は判定タイム（§3.2）に両者まとめて行う
- 公式辞書と追加辞書は別の層として実装する
- 無効の理由は判定タイムで表示する（例：「〜」を使った場合は「長音は「ー」で入力してください」）
- 辞書の読み込み失敗で判定が不公平にならないよう、必要な辞書データを読み込み終えてから回答受付を始める
- **辞書にない言葉は無効。** Ver.0.1 ではプレイヤーによる審議・承認は行わない。追加してほしい言葉は開発側が `extra-words.json` に追記する
- 将来、審議（両プレイヤー承認 → 共有追加辞書）を差し込めるよう、判定は `WordValidator` に集約し、各辞書は非同期インターフェイスにする
- 辞書データの形式：`{ "version": 1, "entries": [["こーひー", "コーヒー"], ["りんご"]] }`（`[読み, 表記]`。表記が読みと同じなら省略）

### 8.2 公式辞書（SudachiDict）

- 元データ：SudachiDict 20260723 の small_lex + core_lex（notcore は収録しない）。Apache License 2.0（`THIRD_PARTY_LICENSES.md`）
- 生成：`python3 tools/build_dictionary.py --download`（元データは `.cache/` に置き、リポジトリには含めない）
- 収録する言葉：
  - 名詞：普通名詞・固有名詞（地名・組織名など）・代名詞。数詞は除く
  - 人名は「姓＋名」のフルネームのみ（例：織田信長）。姓だけ・名だけ（例：ひろし）は無効
  - 住所のように地名が連なったもの（例：千葉県成田市北羽鳥）は除く
  - 動詞・形容詞：基本形（終止形）のみ（例：たべる・うつくしい）。活用形（うつくしかった）・文語形は無効
  - 表記が英字・数字・記号だけの語（略語・欧文。例：SEAPCENTRE）は除く。「Tシャツ」のようにかな・漢字を含む語は残す
  - 読みが130文字以上の語（法律名・標語・極端な複合語など）は除く。最大129文字まで収録する
    （制限時間15秒で130文字以上の入力は実用上不可能なため。130文字未満の長い言葉は有効で、ダメージ計算は §3.4 の上限20文字）
- 読みは kana.js と同じ規則でひらがなに正規化し、「ひらがなと ー のみ・2文字以上」のものだけ収録する
- 同じ読みの言葉が複数ある場合、判定は読みだけで行う。表示用の代表表記は、出題用プールにあればプールの表記、なければ規則（英字なし→正規形→基本語彙→漢字かな交じり→コスト）で1つ選ぶ
- ファイルは「最初の文字 × 最後の文字」ごとに分割（`data/official/<最初>-<最後>.json`、目次 `index.json`）。
  判定ではお題の条件を通った読みしか引かないので、1問につき1ファイルだけ読み込めばよい

### 8.1 出題用プール（prompt-pool）

- 出題と CPU 回答に使う一般語のリスト（`data/prompt-pool.json`、形式は辞書データと同じ）
- 手で整えた日常語 1,025語（名詞が中心。動詞・形容詞の基本形も少し含む）
- お題にするのは、次をすべて満たす「最初×最後の文字」の組み合わせだけ（290組）：
  - 出題できない文字を含まない（§3.6）
  - プール内に候補が2語以上ある（`config.js` の `prompt.minCandidates`）。答えがほぼ1語のお題を避け、CPU の回答にも幅を持たせるため
  - 公式辞書に答えが20語以上ある（極端に難しいお題を避ける。テストで保証する）
- お題は組み合わせ単位で均等に選ぶ。直前と同じお題は続けて出さない
- プールの単語は必ず公式辞書か追加辞書に存在すること（テストで保証する）
